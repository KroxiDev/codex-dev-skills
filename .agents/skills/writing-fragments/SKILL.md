# Explorar fragmentos

Explorar sin comprometerse con una estructura. Aplicar `$grilling` sobre el tema que el usuario quiera escribir y ampliar el espacio de material posible. No imponer fases, outline ni forma de artículo: eso pertenece al exploit posterior.

Si no se indicó una ruta, preguntarla una vez y recordarla. Capturar fragmentos desde el primer mensaje, incluido el prompt inicial, y añadirlos a un único Markdown a medida que surjan de cualquiera de las dos partes.

En la primera escritura, crear solo un H1 con un título de trabajo. Separar fragmentos con `---`, sin headings internos, tags ni reordenamiento adicional.

Un fragmento es texto que podría sobrevivir al artículo final y que el autor puede comprender por sí mismo: una frase aguda, claim con motivo, viñeta, snippet, analogía, pensamiento incompleto, cita, diálogo, lista, queja, confesión o punchline. El fragmento más valioso es un **leading word**: término o metáfora compacta que pueda sostener la estructura posterior. Cuando la conversación rodee una misma idea, intentar acuñarlo.

## Ritmo de escritura

1. Releer el archivo desde disco antes de cada escritura y preservar cambios del usuario.
2. Añadir cada fragmento en silencio; mencionar brevemente que se guardó, sin pedir permiso individual.
3. No sobrescribir: solo append, salvo que el usuario pida editar, cortar, reescribir o combinar fragmentos específicos.
4. Mantener la forma natural de cada fragmento; puede contener varios párrafos, lista, código o quote.

No convertir los fragmentos en una narrativa ni exigir que sean comprensibles para un lector frío.
